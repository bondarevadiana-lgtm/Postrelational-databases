### Лабораторна робота №6

**Назва:** Використання SQL-запитів, тригерів та оптимізація структури зберігання даних в InterSystems IRIS

### Мета роботи :

Освоїти роботу з мовою SQL у середовищі InterSystems IRIS, реалізувати різні типи SQL-запитів (Embedded SQL, Dynamic SQL, COS-based Query), впровадити тригери для автоматизації бізнес-процесів та оптимізувати фізичне зберігання даних за допомогою індексів типу IdKey.

---

### Вихідні дані

Для реалізації застосовано класи системи керування бібліотекою:

- Library.Item (базовий клас, змінено тип індексу на IdKey)
- Library.Book (додано SQL-тригер)
- Library.Magazine (реалізація SQL-запитів)
- Library.Member (реалізація COS-based Query)
- Library.Collection (використання зв’язків Relationship та SQL-курсорів)

Класи містять:

- Індекси типу IdKey
- SQL-запити з параметрами
- COS-based та Embedded SQL-запити
- Dynamic SQL через %SQL.Statement
- SQL-тригери
- Зв’язки типу Relationship
- Підтримку Implicit Join

---

### Основні Завдання Роботи

### 1. Оптимізація зберігання даних (IdKey)

У класі Library.Item унікальний індекс **IDIndex** було змінено на **IDKeyIndex** з використанням прапора **IdKey**.

Результат:

- Фізичне представлення об’єктів у глобалах змінено
- Дані зберігаються безпосередньо за значенням ItemID
- Забезпечено швидший доступ до об’єктів та зменшення витрат пам’яті

Перевірка:

- При перегляді глобала `^Library.ItemD` вузли індексуються за значенням ItemID

---

### 2. Реалізація SQL-запитів

Для кожного класу реалізовано відповідні типи SQL-запитів:

- **SQL-запит з аргументами:**  
  У класі Library.Item реалізовано запит `FindByYear` для пошуку видань за роком публікації

- **COS-based Query:**  
  У класі Library.Member створено запит `ActiveBorrowers`, який використовує методи `Execute`, `Fetch`, `Close` для вибірки активних читачів

- **Embedded SQL:**  
  У класі Library.Collection реалізовано метод `PrintCollectionItems` з використанням SQL-курсора та Implicit Join (`->`) для отримання назв елементів колекції

- **Dynamic SQL:**  
  Реалізовано динамічне виконання SQL-запитів через `%SQL.Statement` для агрегатних обчислень

---

### 3. Робота з SQL-тригерами

У класі Library.Book створено SQL-тригер **LogNewBook**.

Характеристики тригера:

- Подія: автоматично спрацьовує після виконання операції `INSERT`
- Дія: виводить повідомлення або записує лог при додаванні нової книги
- Доступ до даних: використано синтаксис `{Title}` для отримання значень властивостей об’єкта під час вставки

---

### 4. Зв’язки та Implicit Join

Для забезпечення коректної роботи SQL-запитів структура колекцій була змінена:

- Замість простого `list Of` використано зв’язки типу **Relationship** між `Library.Collection` та `Library.Item`
- Це дозволило застосовувати механізм **Implicit Join (->)** для автоматичного об’єднання таблиць у SQL-запитах

---


### Результати

- Успішно оптимізовано архітектуру зберігання даних за допомогою індексів IdKey
- Реалізовано SQL-тригери для автоматизації та логування операцій
- Продемонстровано використання різних типів SQL-запитів у InterSystems IRIS
- Забезпечено коректну роботу Implicit Join через використання зв’язків Relationship
