### Лабораторна робота №8

**Назва:** Проектування та реалізація NoSQL бази даних MongoDB для бібліотечної системи

---

### Мета роботи :

Освоїти принципи документо-орієнтованого моделювання даних у MongoDB, навчитися реалізовувати вбудовані (Embedded) та нормалізовані (Normalized) зв'язки, а також розробити Java-додаток для маніпуляції даними та виконання складних агрегаційних запитів.

---

### Вихідні дані

Структура даних базується на об'єктній моделі з попередніх лабораторних робіт:

- Колекція items: містить документи типів Book та Magazine
- Колекція members: містить дані про читачів та інформацію про їхні запозичення

---

### Основні Завдання Роботи

---

### 1. Моделювання даних у MongoDB

Відповідно до вимог завдання реалізовано дві моделі представлення даних:

- **Embedded Model (вбудована):**  
  Використана для представлення ієрархії бібліотечних предметів. Властивості специфічних типів Book та Magazine (наприклад, author, pages, issue) вбудовані безпосередньо в документи спільної колекції items.

- **Normalized Model (нормалізована):**  
  Використана для реалізації зв’язку типу "один-до-багатьох" між читачем (Member) та предметами бібліотеки (Item). У документі читача зберігається масив ідентифікаторів borrowed_ids, які посилаються на поле _id документів колекції items.

---

### 2. Розробка Java-додатка

Створено Maven-проект у середовищі VS Code з використанням бібліотеки mongodb-driver-sync для взаємодії з базою даних MongoDB.

Реалізований функціонал:

- **Виведення даних:**  
  Підключення до контейнера MongoDB та виведення всіх документів колекцій у форматі JSON

- **Key-Value Query:**  
  Реалізовано пошук документів за декількома умовами одночасно (наприклад, фільтрація за полем type та роком видання year)

---

### 3. Агрегація даних (Aggregation Pipeline)

Побудовано конвеєр агрегації даних, що складається з обов’язкових стадій:

- **$match:**  
  Фільтрація документів (наприклад, вибір читачів, які мають активні запозичення)

- **$lookup:**  
  Об’єднання колекцій members та items за ідентифікаторами документів

- **$unwind:**  
  Розгортання масиву отриманих даних для подальшої обробки кожного предмета окремо

- **$group:**  
  Групування даних за заданим полем (наприклад, за іменем читача) та обчислення агрегатних значень, таких як сумарна кількість сторінок запозичених книг

---

### Результати

- Спроектовано гнучку NoSQL-структуру, що враховує особливості спадкування об’єктів
- Забезпечено цілісність посилань між колекціями шляхом використання нормалізованої моделі
- Продемонстровано можливості агрегаційного механізму MongoDB для отримання складних статистичних даних
